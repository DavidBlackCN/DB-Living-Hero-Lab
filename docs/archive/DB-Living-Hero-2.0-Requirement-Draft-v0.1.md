# DB Living Hero 2.0 — Requirement Draft v0.1

> Status: Archived Draft / Pre-Production（历史快照；当前执行基线见 `../REQUIREMENTS.md`）  
> Project: DB-Living-Hero-Lab 2.0  
> Purpose: 为黑姐姐 1.0 Blog 首页 Hero 场景建立一套“先技术美术、后代码实现”的 Living Hero 2.0 工作流与需求基线。  
> Primary Reference: KumengScreen / 枯梦 · 梦隙  
> 说明：本文件用于约束 2.0 的设计与制作流程。它不是最终视觉提示词，也不是实现代码规格；在主底图设计定型后，应继续细化并冻结。

---

## 1. 项目目标

DB Living Hero 2.0 的目标，是为个人 Blog 首页制作一套高完成度、低干扰、可实时变化的二次元 Hero 场景，使黑姐姐 1.0 在保持角色身份稳定的前提下，呈现出自然、安静、具有“活着感”的动态画面。

目标不是把一张静态插画简单叠加滤镜或局部动画，而是从素材设计阶段开始，为以下能力预留条件：

- 24 小时时段变化；
- 可控的实时重光照；
- 动漫 CG 风格的明暗分档；
- 自然、低幅度的微动效；
- 眨眼；
- 呼吸；
- 可选的轻微发丝运动；
- 克制的 Bloom / 高光响应；
- 适合作为 Blog 首页文字与 UI 背景；
- 可被调试、测试、回归验证；
- 可最终迁移到 DB-Blog-Plume。

最终观感应接近“具有轻微生命感的二次元首页 CG”，而不是：

- 动态壁纸特效堆叠；
- Live2D 式明显变形；
- 强烈游戏 HUD；
- 依赖大量粒子、光污染或夸张镜头效果制造动态感。

---

## 2. 2.0 的核心原则

### 2.1 先设计素材，再设计代码

2.0 必须严格遵守：

> Scene / Art Direction  
> → Base Albedo Design  
> → Technical Art Assets  
> → Asset Freeze  
> → Runtime Architecture  
> → Code Implementation  
> → Visual QA  
> → Blog Integration

禁止重新走 1.0 的路线：

> 先得到一张“已经很好看的成品 CG”  
> → 再尝试用 Shader、Mask、Patch 把它改造成 Living Hero。

2.0 的主图必须从一开始就被视为实时渲染系统的输入资产，而不是完成态宣传插画。

---

### 2.2 美术设计阶段与代码实现阶段分轨

2.0 采用双轨工作流：

#### Art Track
主要负责：

- 场景讨论；
- 主底图构图；
- 角色姿态；
- 光源结构；
- 动效安全区；
- Albedo 设计；
- Normal / Blink / Mask / Region 等技术美术资产；
- 视觉审查；
- 素材冻结。

优先使用官方 GPT 原生订阅环境完成，尤其是涉及图片生成、视觉判断、角色一致性和多轮美术迭代的部分。

#### Code Track
主要负责：

- 项目骨架；
- WebGL / Shader；
- 24h 时间系统；
- Lighting；
- Blink / Breathing / Hair Motion；
- Bloom / Post-processing；
- Debug UI；
- 性能控制；
- 自动测试；
- 回归验证；
- 构建和迁移。

可优先交给中转 GPT / Codex 执行，以降低长时间工程迭代成本。

两条轨道的职责必须清楚，避免再次出现“素材问题让代码补救、代码问题又回头重做素材”的无限循环。

## 3. 角色身份约束

Living Hero 2.0 中的角色仍然是黑姐姐 1.0。

本项目不是角色 2.0 重设计。

以下核心识别点必须稳定继承：

- 米白色 / 奶油色贝雷帽；
- 凋灵玫瑰位于角色头部右侧；
- 黑色丝带仅位于左侧；
- 暖奶茶棕长发；
- 左侧单侧小束发；
- 暖色瞳；
- 小巧、柔软、下颌略圆润但不幼态的脸型；
- 自然睁眼；
- 温和、亲近、略带轻甜感的表情；
- 整体年龄感维持 16–18 岁少女；
- 不转向成熟御姐、幼儿化、冷酷战斗系。

服装可以在黑姐姐 1.0 已确认风格体系内讨论具体场景版本，但必须保持角色身份连贯，不能为了 Shader 便利而重新设计成完全不同的人物。

---

## 4. 视觉基调

目标关键词：

- 安静；
- 温暖；
- 柔和；
- 克制；
- 自然；
- 有轻微生活感；
- 有适度空间层次；
- 深秋 / 初冬氛围；
- 暖灰咖 / 奶油色 / 柔和冷暖对比；
- 适合作为个人 Blog 首页。

避免：

- 高饱和霓虹；
- 夸张镜头光斑；
- 大面积强 Bloom；
- 过量粒子；
- 过度梦幻化；
- 过度复杂背景；
- 强烈“游戏启动页”感；
- 过度写实导致角色与二次元线稿失去统一。

---

## 5. 主底图定位

### 5.1 主图必须采用 Albedo-first 思维

2.0 主图不是最终打光成品，而是后续实时光照的基础颜色层。

应保留：

- 固有色；
- 清晰线稿；
- 材质区分；
- 结构信息；
- 轻微局部色差；
- 足够的褶皱、发束、物体形体信息，以支持后续 Normal 设计。

应尽量避免或禁止：

- 明确方向性的太阳光高光；
- 强烈窗光条带；
- 明显投影；
- 已经烘焙进角色表面的强主光；
- 明显 AO 黑边；
- 强烈环境光遮蔽；
- 强烈台灯打亮效果；
- 成品宣传图式的电影级光影。

核心判断：

> 即使把所有动态光照关掉，主图也应该是“清楚、漂亮、完整的固有色插画”；  
> 但它不应该像“最终调色完成并已打好主光的成品 CG”。

---

## 6. 场景构图要求

### 6.1 基础画幅

默认目标：

- 16:9；
- 优先考虑 2560×1440 或更高分辨率；
- 最终应适配桌面 Blog 首页 Hero；
- 需要明确记录 Artwork Space / Normalized UV。

### 6.2 人物位置

建议：

- 人物位于中间偏右，但不能贴边；
- 人物与文字区之间不能形成巨大空洞；
- 人物头部、脸部、上半身是第一视觉焦点；
- 人物轮廓必须完整、干净、便于技术资产注册；
- 不让复杂前景物体切割脸、头发、肩颈、手等关键区域。

### 6.3 UI / 文字留白

页面需保留一块明确的：

- 低细节；
- 低对比；
- 低纹理密度；
- 视觉稳定；
- 不与脸部争夺注意力

的区域，用于后续 Blog 标题、副标题、导航或轻量信息。

留白必须在底图构图阶段确定，而不是由代码后期用遮罩强行制造。

---

## 7. 光照设计要求

### 7.1 2.0 第一阶段限制光源复杂度

2.0 第一版优先采用：

> 一套主要环境 / 窗外时间光逻辑  
> + 必要但非常弱的辅助环境填充

不建议一开始同时加入：

- 强烈窗户投影；
- 强烈局部台灯；
- 强烈室内环境层；
- 多个需要互相遮挡的局部光源。

如果设计中存在灯具，它应首先作为场景元素或弱 emission，而不是自动成为第二套必须精确处理的主光系统。

### 7.2 光照目标

实时光照需要优先实现：

- Dawn；
- Day / Noon；
- Dusk；
- Night；

但不应只体现为：

- 全局亮度变化；
- 全局色温变化；
- 一层覆盖滤镜。

应通过 Normal + Light Direction + Stylized Shading 让人物和主要大表面产生明确但柔和的体积差异。

---

## 8. 动效需求

### 8.1 Blink

必须纳入首发核心能力。

要求：

- 双眼清楚可见；
- 刘海不过度遮挡眼皮；
- Blink 素材严格注册；
- 优先采用 Open / Half / Closed；
- 只改变眼部，不改变脸型、头发、头饰或构图。

### 8.2 Breathing

必须在底图设计阶段预留安全区。

目标：

- 轻微；
- 连续；
- 自然；
- 可以被肉眼感知，但不能成为明显形变。

应优先作用于：

- 上胸；
- 肩下；
- 躯干主体；
- 大面积连续衣料。

设计时必须避免：

- 手压在主要呼吸变形区；
- 书本、杯子、挂饰穿过变形区；
- 大量长发横跨呼吸区域；
- 硬质结构直接压在可动衣料上。

不应再次出现 1.0 那种只能在极小衣服内部做 1–2 px 位移的局面。

### 8.3 Hair Motion

可作为 2.0 首版“可选但预留”。

底图应至少保留一至数束：

- 轮廓清楚；
- 不贴手；
- 不贴眼；
- 不跨越多个前景物体；
- 可进行轻微 UV / mask deformation

的发束。

不追求整头头发 Live2D 化。

### 8.4 其他动效

可选：

- 极轻微蒸汽；
- 极少量环境粒子；
- 细小反光；
- 背景极轻微层次变化。

禁止让非必要粒子成为“画面活着”的主要来源。

---

## 9. Technical Art 资产要求

在代码正式开工前，至少应考虑以下资产：

### 9.1 Base Albedo
主底图。

### 9.2 Normal Map
用于角色与主要环境表面的实时重光照。

重点描述：

- 脸部广义曲面；
- 大块发束；
- 服装主褶皱；
- 手臂 / 手部；
- 桌面 / 书本 / 杯子等主要物体；
- 主要环境平面。

Normal 以大、中尺度形体为主，不把：

- 睫毛；
- 眉毛；
- 线稿；
- 细碎发丝；
- 纹理噪声

误编码成深度。

### 9.3 Blink Assets
至少：

- half blink；
- closed blink；
- metadata / crop registration。

### 9.4 Semantic / Region Data
至少定义：

- face；
- hair；
- cloth；
- breathing-safe；
- eye / blink；
- optional hair-motion；
- optional steam；
- optional emission；
- important receiver / protected zones。

区域定义的作用是“控制行为”，不是替代 Normal Map 去伪造复杂形体。

---

## 10. Asset Freeze Gate

任何真正的运行时光照 / 动效代码开始前，应至少完成以下验收：

- 主底图构图确认；
- 角色身份确认；
- 主图没有明显 baked directional light；
- 文字/UI 留白确认；
- Blink 可行；
- Breathing 安全区可行；
- Hair Motion 至少有可选区域；
- Normal 与主图可严格注册；
- 主要场景物体不会制造复杂遮挡灾难；
- 光源数量和方向已经确定；
- 技术资产列表已经确定；
- 2.0 不需要依赖“后面用代码再修”的关键美术问题。

只有通过这一 Gate，才允许进入 Runtime / Code Track。

## 11. 正式工作流

### Stage 0 — 设计守则
当前阶段。

输出：

- `Requirement Draft`
- `Scene Design Rules + Forbidden List`

### Stage 1A — Base Scene Design Discussion
使用普通 GPT 官方会话，而不是 Codex。

目标：

- 讨论底图场景；
- 构图；
- 角色姿势；
- 道具；
- 光源；
- 动效安全区；
- UI 留白；
- 视觉叙事。

此阶段禁止直接开工代码。

### Stage 1B — Base Art Direction Freeze
将讨论结果总结为：

- 最终场景说明；
- 主底图生成提示词；
- 负面约束；
- 构图坐标和安全区说明。

### Stage 1C — Art Documentation + Project Scaffold
将已经定型的设计交给 Codex。

Codex 在这一阶段负责：

- 整理 / 补齐剩余技术美术设计文档；
- 建立 `docs/`；
- 建立技术资产目录；
- 建立基础项目框架；
- 建立不依赖最终 Shader 的资产校验、尺寸约束、目录规范等。

此阶段仍不得擅自把未冻结素材替换成“代码补救方案”。

### Stage 2 — Asset Production & Review
优先使用官方 GPT 完成：

- Base Albedo；
- Normal；
- Blink；
- 必要 Mask / Region / auxiliary assets。

每一项都必须人工验收。

### Stage 3 — Asset Freeze
形成不可随意修改的 2.0 第一版素材包。

### Stage 4 — Runtime Implementation
交给 Codex / 中转 GPT：

- WebGL；
- Lighting；
- Timeline；
- Animation；
- Post-processing；
- Debug；
- Tests。

### Stage 5 — Visual Acceptance
优先评价：

- 整体视觉；
- 时段差异；
- 角色生命感；
- 是否自然；
- 是否适合作为 Blog Hero。

工程测试用于防止回归，但不能替代人工视觉验收。

### Stage 6 — Blog Integration
只有 Living Hero Engine 与素材均冻结后，才迁移进 DB-Blog-Plume。

## 12. 2.0 成功判据

2.0 成功不以“功能数量”判断。

第一版成功应至少满足：

1. 静态底图本身已经明显优于 1.0 的母图；
2. Noon / Dusk / Night 的光照结构有明显差异，而不是滤镜差异；
3. 人物脸部在所有时段都保持自然；
4. Normal 重光照让头发、衣物、大表面产生可信体积；
5. Blink 自然；
6. Breathing 肉眼能感知，但不明显变形；
7. 不依赖大量局部 patch 才能维持画面；
8. 没有因为窗框、台灯、书本、手等小物体反复产生大量 code-only salvage；
9. 页面在加入 Blog 文字/UI 后仍然保持完整构图；
10. 与参考项目相比，至少达到同一层级的整体协调度，再通过角色设计、场景氛围和 Blog UI 形成自己的优势。

---

## 13. 2.0 明确不追求的事项

第一版不强求：

- 真实物理阴影；
- 三维光线追踪；
- 多点局部灯；
- 复杂景深；
- 大规模粒子系统；
- 大范围视差；
- 完整 Live2D；
- 高幅度人物动作；
- 复杂角色交互。

这些都不能以牺牲主视觉质量为代价提前加入。

- 1.0 保留作为经验、代码和失败案例参考；
